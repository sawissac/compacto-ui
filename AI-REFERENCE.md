# AI-REFERENCE

How an AI coding agent (or the `shadcn` CLI) should consume this repo. There
is no npm package — every component is copied into the consuming app's own
source tree, the same pattern as shadcn/ui.

## Manifest

[`registry.json`](registry.json) at repo root lists every item: `name`,
`type`, `description`, `dependencies` (npm packages to install),
`registryDependencies` (other items in this same registry to resolve first),
and `files` (`source` path in this repo → `target` path in the consumer).

Built, self-contained artifacts — with each file's source inlined as
`content` (this repo's own components already import each other via `@/...`,
the same alias shape a copy needs) — live at `public/r/<name>.json`, one per
item, plus an index at `public/r/registry.json`. These are hand-maintained
snapshots, not generated by a script — when you edit a component, edit its
`public/r/<name>.json` `content` to match, and `registry.json` if its
`dependencies`/`registryDependencies` changed.

Prefer reading the built `public/r/<name>.json` files over the source
`registry.json` — they're what actually gets copied; `registry.json` only
records where things come from.

## Item types

- `registry:ui` — a component. Target: `components/ui/<name>.tsx`.
- `registry:lib` — a shared helper (`cn`, `ui-styles`, `color-themes`).
  Target: `lib/<name>.ts`.
- `registry:file` — plain files copied as-is (`styles`, `compat-shadcn`).
  Target: `styles/compacto/<file>.css`.

## Resolution algorithm

Given a request for component `X`:

1. Read `public/r/X.json` (or `registry.json`'s `src/...` source directly, if
   the built artifact isn't available).
2. For every name in `registryDependencies`, recurse — resolve and copy it
   first, deduped (`cn` is a dependency of nearly everything; write it once).
3. Union every `dependencies` entry across all resolved items into one
   `pnpm add` (or `npm install` / `yarn add`) call.
4. Write each resolved item's `files[].content` to `files[].path` in the
   consumer app, creating directories as needed. Do not silently overwrite a
   file that already differs from the registry version — ask, or diff.
5. If the consumer has never installed the `styles` item, copy it too — every
   component assumes `--app-*` variables exist. `compat-shadcn` is opt-in
   only (see README's "Migrating from shadcn semantic tokens").

## Conventions the copied code assumes

- Path alias `@/*` resolves to the consumer app's `src/` (or app root) —
  standard for a Next.js app scaffolded with `create-next-app` or an existing
  shadcn/ui setup. If the target app uses a different alias, rewrite imports
  accordingly after copying.
- Tailwind v4 with the `app-*` color namespace generated from `--app-*`
  variables (see `styles/compacto/tokens.css` and `theme.css` after copying).
- React 19 (`ref` as a plain prop — the components never `forwardRef`).

## What NOT to do

- Don't `npm install @compacto/ui` or `npm publish` from this repo — that
  flow was removed. There is no registry package.
- Do keep `public/r/*.json` and `src/**` in sync by hand — there is no build
  script; a stale `content` field is a silent lie to whoever copies it next.
- Don't invent a `target` path other than what the item specifies unless the
  user asks for a different layout — the whole point of a fixed convention is
  that components' `registryDependencies` imports (`@/components/ui/button`,
  `@/lib/cn`) resolve without per-copy edits.
